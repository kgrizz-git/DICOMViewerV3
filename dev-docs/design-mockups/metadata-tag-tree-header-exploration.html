Left Metadata Pane — Group Header Proposals

Root issue found: the current header fill sits almost exactly on the main window's chrome color (#f0f0f0 light / #1e1e1e dark — confirmed in metadata_table_model.py's own comment). The "soften" commit pushed the light-theme header toward white, which crosses through that chrome value instead of moving away from it. All proposals below fix the direction first, then add a touch more separation and a 1% accent tint for a bit of chroma. Each is shown in a wireframe app window (menu bar / toolbar / viewport are placeholders — only the left pane is "real").

New Batch — Accent lives only on the header; rows go pure grayscale

Two changes requested: (1) move all the accent color budget onto the header band and make the alternating tag rows plain low-contrast greys instead of accent-tinted; (2) header separators use a bottom-only border/rule — never a top one. That's the fix for the collapse case: if a header's bottom edge is immediately followed by another header (an empty/collapsed group), a top+bottom pair on adjacent headers would double up into one heavy line. With bottom-only borders, two stacked headers still show exactly one line between them. A small proof strip is included in each proposal.

Third Batch (revised) — A's fill + A's top hairline + a thin bottom border added

Correction from the previous round: keep Proposal A's top hairline (it wasn't being dropped after all — you want it back), and add a thin bottom border alongside it rather than replacing it. "Thin" is done via alpha rather than width, same as before, since a true sub-pixel border isn't renderable crisply in CSS or Qt: the bottom border is 1px at ~14% opacity so it reads as a soft close rather than a second hard rule. Trade-off to flag: having both a top and a bottom border brings back the collapse-adjacency problem from two rounds ago — when a group is collapsed and one header sits directly above another, header 1's bottom border and header 2's top border now sit right next to each other and read as one slightly heavier line. Each proof strip below shows exactly what that looks like so you can judge whether it's noticeable enough to matter.

Sixth Batch — Light C confirmed; two new directions

Light C's fill/border combo is the new baseline for light theme. Worth noting: since the pane now has its own outer frame (L3), the header-vs-chrome collision risk that drove most of this exploration matters less than it used to — the frame itself already marks the pane's boundary, so colors near the chrome value are safer than they were in the frame-less early rounds. That headroom is what makes N1 viable. N2/N3 flip the whole model: instead of the header being the darker band, the tag rows get a light grey wash and the header becomes the brightest element in the pane, popping up rather than receding.

Since the fill barely separates from either neighbor on its own, the border alpha is bumped to 22% (from Light C's 18%) to do correspondingly more of the defining work.
