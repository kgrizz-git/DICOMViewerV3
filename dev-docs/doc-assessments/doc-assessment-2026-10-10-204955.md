# Focused documentation assessment — MPR sessions engine (PR-A)

**Date:** 2026-10-10
**Scope:** The engine slice of the multi-session MPR change (session/view
registry, admission limits and approximate memory, fenced builds with atomic
activation rollback, closure release). Parking (detached views, navigator
tiles, drags), duplication and linked scrolling are **not** in this slice and
are not documented as present.
**Method:** code-verified against `src/` and the retained tests on the PR-A
branch; not exercised in the running app (real-display manual smoke remains
tracked in `TO_DO.md`).

## Findings

- `user-docs/USER_GUIDE_MPR.md` (DOC-07): rewritten for the engine slice —
  opening/building, interim Clear-Window semantics (park action unavailable
  on MPR panes; use **Clear MPR View**), limits and memory, save as DICOM.
  No tiles, parking, duplication or linking are documented as present.
- `user-docs/CONFIGURATION.md` (DOC-04): **MPR Limits** group and the
  `mpr_session_cap` / `mpr_view_cap` keys verified against
  `src/utils/config/mpr_session_config.py` (strict int validation, pair
  invariant, atomic save) and `src/gui/dialogs/settings_dialog.py`
  (spin ranges follow the pair invariant).
- `ARCHITECTURE.md` (DOC-14) and the module tree: registry-ownership and
  canonical-setter rules updated to the engine slice; helper rows list only
  modules present in this slice.
- Status-line and refusal strings in the guide match
  `gui/mpr_admission.py` exactly (`MPR: 2/8 sessions, 3/16 views, about 410 MiB
  (estimate)`).
