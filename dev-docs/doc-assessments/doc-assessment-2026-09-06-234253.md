## Findings

### F1 — 17 documentation references named source files that had moved (WRONG)

A `core/` to `gui/` package move was never reflected in prose. Seventeen inline
`src/...py` paths across six living documents named files that do not exist,
including `src/core/mpr_controller.py` (actually `src/gui/mpr_controller.py`),
`src/core/qa_app_facade.py`, `src/core/export_manager.py`,
`src/core/app_signal_wiring.py`, and `src/core/view_state_manager.py`.
Affected: `ARCHITECTURE.md`, `dev-docs/HARNESS.md`,
`dev-docs/SECURITY_IMPLEMENTATION_SUMMARY.md`,
`dev-docs/info/DICOM_SUPPORT_ANALYSIS.md`,
`dev-docs/info/PYLINAC_SAGITTAL_DISTORTIONS_INVESTIGATION.md`,
`dev-docs/info/SOURCE_LAYOUT_MODULE_TREE.md`. **All 17 corrected.**

### F2 — 12 of 20 links in the code documentation index were broken (WRONG)

`dev-docs/CODE_DOCUMENTATION.md` linked twelve documents at `dev-docs/` root
that had been relocated to `dev-docs/info/` and `dev-docs/plans/completed/`.
The index is the entry point agents are told to read, so every one of those
was a dead end. **All 12 corrected.**

**Root cause for F1 and F2:** `check_user_docs_links.py` covered `user-docs/`,
`README.md`, and `dev-docs/README.md` only — 14 files. No check ever read the
developer documentation, so both classes of rot were invisible. See *Enforcement
added* below.

### F3 — ARCHITECTURE.md dependency rules contradicted the code (WRONG)

The rule block stated `core/ → utils/, other core/`, but
`src/core/roi_export_service.py:34` imports `tools.angle_measurement_items` and
`tools.measurement_items`. The block also omitted `tools/` and `qa/` entirely
despite both being top-level domain packages that other rules referenced.
**Corrected**, and the real `core/ → tools/` edge is now documented as
deliberate so it is not "fixed" by tightening the rule.

### F4 — Stated boundaries were broader than what is enforced (GAP)

The section was titled "enforced by convention" but read as though the whole
block were checked. `check_architecture_boundaries.py` rejects only four edges:
`core/ → gui/`, `utils/ → {gui, core, main, roi, metadata, tools}`,
`gui/ → main`, and `{roi, metadata} → main`. **Corrected** with an explicit
"What is actually enforced" paragraph naming those four, so the unenforced
remainder is visibly convention.

### F5 — Two significant packages were absent from the domains map (GAP)

`src/gui/volume/` (12 modules) and `src/utils/privacy/` (12 modules) appeared in
no domain table or module tree. Privacy is a core concern of this application.
**Corrected** in `ARCHITECTURE.md` and `dev-docs/info/SOURCE_LAYOUT_MODULE_TREE.md`.

### F6 — Wrong entry point for adding a menu action (WRONG)

`ARCHITECTURE.md` "Where to change what" sent contributors to `src/core/actions/`,
which holds only `customization_actions.py`. View and dialog actions live in
`src/gui/actions/`. **Corrected.**

### F7 — CONTRIBUTING.md CI guidance was inverted (WRONG)

It instructed contributors to use "current **major tags** for first-party actions
(`actions/checkout@v6`, `actions/upload-artifact@v7`, `github/codeql-action/*@v4`)".
Every first-party action is in fact pinned to a full commit SHA with the version
in a trailing comment, and checkout is at v7, not v6. A contributor following the
document would have loosened a deliberate supply-chain pin. **Corrected.**

### F8 — Two wrong module paths in SOURCE_LAYOUT.md (WRONG)

`core/app_signal_wiring.py` (actually `gui/`) and
`core.actions.view_actions.on_privacy_view_toggled` (actually `gui.actions`).
**Corrected.** Found by the stepfun review lane and independently confirmed.

### F9 — CHANGELOG compare links point at tags that do not exist (WRONG, not fixed)

`CHANGELOG.md` ends with five comparison links referencing `v0.1.0`, `v0.1.1`,
`v0.1.2`, `v0.4.0`. The repository has **zero** Git tags, locally and on the
remote (`git tag | wc -l` → 0; `git ls-remote --tags origin | wc -l` → 0). All
five links 404 on GitHub. `RELEASING.md` steps 5 and 6 instruct tagging, so the
documented release process has never actually been run to completion.

**Not fixed here, deliberately.** The remedies are to create retroactive tags or
to remove the links, and both are release-policy decisions for the maintainer
rather than documentation edits. This is the same missing release boundary that
blocks the release-assessment trigger in the workflow plan. Tracked as
**TRIAGE-039**.

### F10 — DEVELOPER_SETUP.md misattributed the privacy gate (WRONG)

It stated that `scripts/git-hook-security-gate.py` invokes
`scripts/git_hook_privacy_checks.py` "on every pre-commit and pre-push
invocation". Neither half holds. The hook scripts call the privacy check
directly (`.githooks/pre-commit:53`, `.githooks/pre-push:35`); the security gate
runs `run_security_scan.py` (`git-hook-security-gate.py:71`) and is gated to
`main` (`should_scan_pre_commit`, `should_scan_pre_push`), so it never runs on a
feature branch. A contributor debugging a blocked commit would have looked in the
wrong script. **Corrected.**

### F11 — A documented diagnostic command could never have worked (WRONG)

`DEVELOPER_SETUP.md:62` gave
`python -c "from core.decoder_capabilities import ..."` for checking installed
decoder handlers. Run as written it fails with
`ModuleNotFoundError: No module named 'core'`, because `core` is only importable
with `src` on the path; every other command in the document carries the
`PYTHONPATH=src` prefix. With the prefix it prints
`('GDCM', 'pylibjpeg', 'Pillow')`. **Corrected**, including the expected output.

### F12 — HARNESS.md omitted the entire git-hook layer (GAP)

The "Layer 3 — Mechanical checks" table listed five scripts. The installed hooks
run about twenty more, nearly all blocking: twelve on `pre-commit`, eleven on
`pre-push`, one on `commit-msg`. The most blocking layer in the repository was
undocumented in the document whose subject is the harness. **Corrected** with a
per-hook table in execution order, plus the note that the security gate is
branch-gated to `main`.

### F13 — Pre-push hook stated the wrong coverage gate (WRONG)

`.githooks/pre-push:48-49` told developers "CI owns suite + 65% coverage" and
suggested `--cov-fail-under=65`. CI actually gates at **80**
(`.github/workflows/ci.yml:127`), which `DEVELOPER_SETUP.md:337` already stated
correctly. A developer trusting the hook would think a run passing at 70% was
fine. **Corrected in the hook**, this being developer-facing text rather than a
behavior change; the 65% figure remains in `MAINTENANCE_LOG.md` as accurate
history of when the gate was lower.

## Enforcement added

The two largest findings existed because nothing read the developer docs.
`scripts/check_user_docs_links.py` now:

- covers the living `dev-docs/` (top level and `info/`), `ARCHITECTURE.md`, and
  `AGENTS.md` in addition to `user-docs/` and `README.md` — **14 files to 69**;
- validates inline `src/...py` code paths, not only Markdown links, which is the
  specific check that catches a package move;
- excludes `dev-docs/plans/`, where **150** broken links are expected: completed
  and supporting plans describe the tree as it was when written and are history.
  `CHANGELOG.md` is excluded for the same reason — its released entries name
  modules that have since moved, and 15 such references are accurate history
  rather than rot.

Verified against `origin/main`: **31 findings**, versus 0 on this branch. Five
regression tests were added in `tests/test_user_docs_links.py` covering a moved
module, a correct path, illustrative `src/...py` prose, directory and glob
mentions, and the `plans/` exclusion.

## Known limits of the new check

Surfaced by external review, demonstrated, and accepted rather than fixed:

- **Instructional prose is flagged.** A name in inline code is read as a claim
  that the file exists now, so "create `src/my_thing.py`" would fail. Write a
  proposed file as a directory, a glob, or plain prose. Accepted: the alternative
  is an exemption marker, which is a bigger hole than the problem.
- **`CHANGELOG.md` is not scanned.** It holds 15 references to modules that have
  since moved; each was accurate for its release. Same rationale as excluding
  `dev-docs/plans/`, and now stated in the script's docstring.

## Rejected findings

Reported by a review lane, not reproduced, no action taken:

- **`src/qa/`, `src/core/study_index/`, and `src/tools/` are undocumented in
  `SOURCE_LAYOUT.md`.** That document scopes itself as a "Compact controller,
  bootstrap, and signal-wiring index" and explicitly delegates file-level
  navigation to `info/SOURCE_LAYOUT_MODULE_TREE.md`, which does cover them. Not a
  gap. (`src/gui/volume/` was absent from *both* and is F5.)
- **Expand `check_architecture_boundaries.py` to forbid `core/` importing
  `roi`, `metadata`, `tools`, `main`.** Rejected as a documentation change and
  wrong on the merits: `core/ → tools/` exists in shipped code (F3), so the
  suggested rule would fail the build immediately.
